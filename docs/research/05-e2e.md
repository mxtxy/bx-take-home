# Research: E2E

## Question

Can the reviewer validate the product through Docker Compose and browser flows?

## Source of Truth

`codex/TEST_SPEC.md`, Playwright, and the running Compose stack.

## Decision

Use Playwright against `http://localhost:3000` with the backend at `http://localhost:8080`.

## Risks

E2E tests are slower and require a clean seeded database for deterministic flows.

## Tests Added

Assignment, completion, conflict, reschedule, and unauthorized update flows.

## Follow-Up

Add CI orchestration with service health waits and trace artifacts.
